# MCP panel implementation plan

Goal: Add `/mcp` to Difu's terminal UI for both coding providers, showing the active session's servers and tools with enable/disable, reconnect, and authentication actions.

Architecture: A shared typed MCP inventory and action model, provider-specific control requests over the existing worker connections, and a native terminal modal. Never send `/mcp` as a model prompt or use a separate connection to represent the active runtime. Claude uses its MCP control requests. Codex uses its status, configuration-write, reload and OAuth APIs; expose reload/configuration scope clearly.

- [x] Add inventory normalization tests, including disabled/failed servers, unknown state, tools, and credential exclusion.
- [x] Implement shared MCP actions/results and route requests to live workers without starting model turns.
- [x] Implement Claude control operations and Codex paginated inventory, configuration toggle/reload and OAuth.
- [x] Add `/mcp` panel, keyboard navigation, server/tool details, action progress, errors and stale-response protection.
- [x] Verify with Rust tests, formatting/lints and isolated local MCP servers against installed providers.

Constraints: Preserve session/history behavior; no config edits when opening the panel. No credentials or full provider configuration in UI results or session persistence. Disabled servers remain visible. Do not claim connected from a nonempty tool cache. Codex configuration changes must identify their scope; unsupported provider capabilities must report actionable errors. All actions target the selected session captured when the panel opens.

Validation: full Rust suite passed (371 tests, 4 ignored (including the opt-in visual preview exporter)); formatting and Clippy with warnings denied passed. Isolated installed-provider probes verified connect/disable/enable/reconnect with a synthetic stdio MCP server on Codex 0.163.0 and Claude 2.1.302, without model turns or real configuration changes. Provider-service fixtures cover paginated discovery, OAuth initiation, active-worker routing and preservation of interleaved Claude approvals. Real-account OAuth completion was not exercised. Terminal render checks cover server list, details, tools and narrow sizes. Independent review found the approval-interleaving issue; the regression failed before the fix and passed afterward, and follow-up review found no further substantive issues.

Final UI: full-width terminal surface with source groups, semantic status icons, aligned tool counts, labeled server metadata, numbered actions, and a footer below the content. Grouped selection survives refresh and back navigation. Version 0.20.2 upgrades incompatible 0.20.0 services. Service-restart tests verify MCP reconnection does not send a model prompt. The user verified the final layout in Difu.
